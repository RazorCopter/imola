# Functional Gap Analysis — Fase 7, Blocco 0000

## Scopo e criterio di valutazione

Questa è l'unica matrice canonica della gap analysis funzionale. La valutazione è basata sulle evidenze presenti nel workspace al 22/10/2026; non attribuisce completamento sulla base del solo piano o del nome di un test.

Stati ammessi e applicati una sola volta per capability:

- **COMPLETA**: API reale con autorizzazioni e test backend; GUI raggiungibile con form o interazione completa, validazione, conferma e feedback; E2E Playwright reale che esegue il comportamento (per una mutation: la mutation effettiva) e verifica la persistenza via API o UI dopo reload; nessun placeholder/hardcode; verifica manuale con utenti demo documentata. Per capability consultive l'E2E deve verificare dati reali e comportamento utile, non soltanto heading o navigazione.
- **PARZIALE**: esiste un percorso funzionale significativo, ma manca almeno un elemento della DoD completa (tipicamente E2E reale/persistenza, feedback/validazione, copertura permessi o verifica manuale demo).
- **SOLO BACKEND**: dominio/API/CLI e test backend esistono, ma non esiste una GUI utente corrispondente e completa.
- **NON IMPLEMENTATA**: manca il percorso funzionale richiesto, oppure quanto presente è solo placeholder, test nominale, hardcode o struttura dati non esposta come comportamento utilizzabile.

Le suite Playwright di Fase 3 intercettano le API con `page.route`; quelle di Fase 4 usano login e dati reali ma controllano soltanto navigazione/contenuti; quelle di Fase 6 hanno titoli che dichiarano mutation, ma non invocano le mutation né verificano persistenza dopo reload. Di conseguenza nessuna di queste evidenze, da sola, soddisfa la DoD stretta.

- **Fase 6 / amministrazione**: il `PlaceholderPage` e la voce `/amministrazione` sono stati rimossi, ma la GUI amministrativa non è stata implementata; FG-038 resta NON IMPLEMENTATA e la rimozione deve essere valutata nella verifica manuale.

- **Run controlli**: l'E2E reale esegue la mutation e verifica anomalie persistite dopo reload/API, ma feedback completo e verifica manuale mancano; FG-020 resta PARZIALE.
- **KPI a zero**: backend e GUI distinguono dati assenti/non verificabili e non mostrano successo verde; manca ancora un E2E dedicato a ciascun caso limite e la verifica manuale, quindi FG-018 resta PARZIALE.

## Priorità di remediation dopo il Blocco 0000

1. Rendere reali gli E2E delle mutation già esposte: creazione/modifica/chiusura progetto, regolazione wallet, run controlli, risoluzione/deroga; verificare persistenza via API o UI dopo reload.
2. Rimuovere hardcode e azioni implicite, aggiungendo conferma, validazione e feedback osservabile.
3. Chiudere i gap di dominio espliciti: assegnazione a persona/architetto, consumo/residuo per assegnatario e mapping Excel storico → schema 1.0.0.
4. Correggere e specificare la semantica KPI nel caso riconciliazione vuota.
5. Sostituire amministrazione placeholder e portare in GUI import/export/rollback/audit generico secondo priorità e permessi.
6. Eseguire e registrare una verifica manuale ripetibile con utenti demo per ruolo.
